## What this session did

1. **Diagnosed a "regression" that wasn't** — the user passed a path to `--curriculum`; the script took a bare name, matched nothing, and the container's seed script fell back to the alphabetically-first curriculum (`intro-agents`). Claude Code was fine; it starts when a Terminal is opened, which the screenshot hadn't done. Evidence: `docker logs jupyter-student01` on the then-running box showed `WARNING: curriculum '/Users/johndamask/scratch/...' not found ... falling back to 'intro-agents'`.
2. **`--curriculum` takes a directory; one curriculum per class** (438299c). `resolve_curriculum()` in `scripts/workshop` validates before any AWS call (`lessons/` required, non-empty; name without spaces). Only that directory ships, its *contents* land at `/opt/lab/curriculum`, the hub mounts it there, `seed-home.sh` copies from there with no selection and no fallback. `LAB_CURRICULA_DIR`, `LAB_CURRICULUM`, `LAB_CURRICULA_HOST_DIR` are all gone; one var `LAB_CURRICULUM_HOST_DIR` remains for the hub. Why one-per-class: the user ruled "the lab curriculum directory should be a constant for students; only the content changes." Both tars got `--no-xattrs` (the `LIBARCHIVE.xattr.com.apple.*` warnings the user first asked about).
3. **TLS certificate persists across instances** (3c855b6). `infra/durable.yaml`: private, versioned `CertBucket` (Retain), instance role gets ListBucket/GetObject/PutObject only. `scripts/cert-sync.sh` (new, baked into the AMI at `/opt/lab/cert-sync.sh`): `restore` runs as Caddy's `ExecStartPre=+`, `save` runs from a 5-minute systemd timer, from `up` after https answers, and from `down` before terminate. `build` dies if the stack has no bucket; `up` warns if the stack predates it; `up` now greps Caddy's journal for `rateLimited` and prints the retry time instead of "check Caddy".
4. Verified Let's Encrypt's rule against their live rate-limits page: 5 per exact identifier set per 7 days, global, no override, ARI renewals exempt.

## Recommended next — this session's view

I'd run one real cycle after 2026-09-23 20:37 UTC: `init`, `build`, `down`, `up --students 8 --curriculum ~/scratch/go-exercises/go-curation`. It is the only thing that turns both of this session's changes from "passes on a laptop" into "works", and the certificate it obtains is the one every later `up` reuses — so it should be obtained on the new AMI, where it gets saved. Doing the cycle *before* the limit lifts wastes the attempt (https fails identically) and, if done on the old AMI *after* it lifts, spends a certificate that is then thrown away at `down`.

Consequence of skipping: the next teacher who rehearses more than four times in a week gets an unreachable class, which is exactly what happened today.

## Decisions and rules

- **`lessons/` is required in a curriculum.** User confirmed ("you're right for making lessons required"). `CLAUDE.md`, `welcome.txt`, `skills/` stay optional (warn only).
- **No fallback curriculum, anywhere.** Missing mount = ERROR in the log + base files + `base-only` marker. Silently teaching the wrong thing was the original bug.
- **Instance role cannot delete from the bucket.** `save` runs `s3 sync` without `--delete`; a fresh box with nothing can't wipe a good certificate.
- **Certificate bucket is `DeletionPolicy: Retain`.** A non-empty bucket would otherwise fail the stack delete. Documented in the template comment; `aws s3 rb --force` cleans up.
- **`cert-sync.sh` is never fatal.** Caddy must start even if S3 is unreachable; it just requests a certificate like before.
