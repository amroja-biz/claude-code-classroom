## What this session did

Built the whole thing from nothing. Nine commits, `3ead4c5` through `157cd4c`.

- **Architecture** (`docs/SPEC.md`): one EC2 instance, Docker, Caddy. JupyterHub
  runs *in a container* and spawns sibling student containers through the Docker
  socket, so `docker-compose.yml` is identical locally and on the box. Rejected
  ALB/NAT/ECS/EKS/EFS/Cognito — ~$50/month of fixed cost before anyone logs in.
- **Per-student isolation** via DockerSpawner with `mem_limit`. The reference
  project needs an 8 GB swapfile because one runaway agent can livelock a shared
  box; a cgroup cap makes that structurally impossible.
- **Code-based auth** — a ~10-line `CodeAuthenticator` plus a single-field login
  template (`hub/templates/login.html`). Codes regenerate per cohort, so the
  previous cohort's stop working with no revocation step.
- **Curriculum system** — material is data, not code. All curricula are baked
  into the image; `$LAB_CURRICULUM` selects one at spawn time, so switching
  cohorts is a flag rather than a rebuild.
- **Derived sizing** (`scripts/lib-size.sh`) — instance type and root volume are
  computed from `--students`. There is deliberately no default cohort size; the
  test suite fails if a hardcoded one reappears.
- **Lifecycle** (`scripts/workshop`) — `discover`, `init`, `build`, `up`, `down`,
  `size`, `status`. Verified end to end on real AWS including TLS issuance, code
  login, container spawn, concurrent multi-student isolation (the user confirmed
  two browsers, two codes), and teardown.
- **Secrets** — API key in SSM Parameter Store, fetched by the instance under its
  own IAM role. Never transits the operator's SSH session.
- **Install skill** (`.claude/skills/claude-classroom-aws-setup/`) — the user
  objected, correctly, that expecting humans to read a README and type VPC IDs
  is the wrong interface. The skill drives an agent through discovery, config,
  deploy, DNS delegation and verification.

## Recommended next — this session's view

If it were my call: **have an agent actually run `/claude-classroom-aws-setup`
against a scratch AWS account.**

It is now the primary documented install path — the README leads with it and
keeps manual setup collapsed — and it is the only major component never
executed. Everything else in this repo was verified against live AWS, some of it
three times. The skill was verified against a grep. That asymmetry is the
biggest risk in the project: the first external user's first experience runs
entirely through the least-tested artifact.

Concretely, the parts I'd expect to break are the ones a static check cannot
cover: whether the agent correctly matches a hostname against existing hosted
zones and picks the simple same-account path, whether the DNS delegation loop
actually blocks until `dig` resolves, and whether the API-key step really keeps
the value out of the agent's context.

**Consequence of skipping:** low operational risk — nothing is running and
nothing degrades. The cost is reputational and lands on someone else: a stranger
clones the repo, runs the headline command, and hits a flow nobody has walked.

The AWS resource rename (thread 1) is the other in-scope item. It is
cosmetic and carries a real hazard — re-delegating DNS across accounts is the
step most likely to leave the deployment broken in a way that looks like a TLS
bug. I would not do it immediately before a workshop.

## Decisions and rules

- **One repo, config parameterized — not a public fork.** A fork rots: you run
  the private one daily and the public one never. `workshop.conf` (gitignored)
  holds everything account-specific.
- **MIT, with `NOTICE` retaining go-jupyter's BSD 3-Clause notice.** Measured:
  ~105 of ~1,870 code lines (6%) are derived, and those are ~1% of their source.
  Only the `.claude.json` seeding block is a genuine port.
- **Never attribute commits to Claude Code or Anthropic** — the user's global
  CLAUDE.md rule; it overrides the harness's attribution reminder.
- **Parameter Store, not Secrets Manager.** Standard-tier SecureString is free;
  Secrets Manager is $0.40/secret/month for automatic rotation that cannot apply
  to an Anthropic key. Idle cost near zero is a stated project principle.
- **r7i, not t3.** Burstable credits deplete when a whole cohort runs an exercise
  simultaneously — exactly the workshop access pattern.
- **No default cohort size.** `--students` is required and everything derives
  from it. `scripts/test-size.sh` greps `scripts/` and fails if a hardcoded
  default reappears.
- **The root volume is ephemeral** (`DeleteOnTermination=true`), so a large
  in-session disk costs nothing between classes. Disk is sized for *tool caches*
  (`15 + 5 GiB/student`), not authored files — the reference workshop needed
  150–200 GB for ~40 people because of `uv`/`pip`/`npm` caches.
- **Ephemeral resources stay out of IaC.** CloudFormation holds only durable
  things; the instance and volume are created by scripts. Modelling a
  "exists on Tuesdays" instance declaratively is what forces `prevent_destroy`
  guards.
- **Deferred, with a trigger** (`docs/SPEC.md` §14): splitting boot and data
  volumes. Revisit when a curriculum ships real data — before that, fetch large
  class data from S3 at `up` time instead.

## Traps

Every one of these cost real time this session.

- **`aws ec2 wait image-available` gives up after 10 minutes** (40 × 15s). A
  first AMI snapshot exceeds that. Worse, `set -e` then fired the EXIT trap,
  which **terminated the build instance mid-snapshot at ~70%**. It survived only
  because AWS continues a `CreateImage` snapshot after termination. Now a
  60-minute polling loop, and the trap is disarmed the moment `create-image`
  returns.
- **docker-stacks *sources* `before-notebook.d/*.sh` into `start.sh`.** A
  `set -euo pipefail` in a hook leaks `set -u` into the parent, which dies on its
  own unset `JUPYTER_DOCKER_STACKS_QUIET`. Symptom: container starts, never
  serves, and `remove = True` deletes it before you can inspect it. The hook is
  now a one-line wrapper invoking a subprocess.
- **Claude Code is a Bun binary and crashes under QEMU.** An `linux/amd64`
  student image on an Apple Silicon Mac serves JupyterLab perfectly but Claude
  Code dies with `MemoryExhaustion` → `qemu: uncaught target signal 6`. Looks
  like a Claude Code bug; is not. `make dev-build` native, `make prod-build` amd64.
- **JupyterHub 5.0+ requires `c.Authenticator.allow_all = True`.** Without it a
  valid credential authenticates and is then denied at authorization.
- **DockerSpawner mounts a named volume over `/home/jovyan`**, shadowing anything
  baked there. Content lives in `/opt/lab/` and is copied in at container start.
- **Route53 JMESPath needs spaces around `&&` and a pipe to index the match.**
  `[?Name=='x'&&Type=='A'].ResourceRecords[0][0].Value` returns empty silently;
  `[?Name=='x' && Type=='A'] | [0].ResourceRecords[0].Value` works. The broken
  form made `down` leave DNS pointing at a terminated instance.
- **`curl -sf` without `-k` always fails against a Let's Encrypt staging cert**,
  so `up --staging` reported a perfectly working deployment as broken.
- **zsh does not word-split unquoted variables.** `SSH="-o A -o B"; ssh $SSH host`
  collapses into one argument. Inline the options or use an array.
- **Do not edit a script while a background job is about to exec it.** A
  truncate-then-write mid-flight made bash read a partial file and die with a
  syntax error at a line that was fine before and after.
- **EC2 security group rule descriptions reject `>`.** Allowed set is
  `a-zA-Z0-9. _-:/()#,@[]+=&;{}!$*`. "Caddy -> JupyterHub" fails the whole stack.
- **A failed CloudFormation CREATE leaves `ROLLBACK_COMPLETE`**, which cannot be
  updated. Delete the stack before redeploying.
- **An instance cannot have a root volume smaller than its AMI's snapshot.** The
  build volume sets a permanent floor for everything launched from that AMI.
  Build small.
- **`deregister-image` does not delete the backing snapshot.** It bills forever.
  `workshop build` prunes both.
- **The `dcg` guard blocks `rm -rf` and `rm -r` even inside heredocs** that are
  merely *writing* those strings into a file. Use `find ... -depth -delete`.
