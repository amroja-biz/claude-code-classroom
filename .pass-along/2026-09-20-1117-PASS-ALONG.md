## What this session did

Five commits, `2f16743` through `9312e7a`.

**Containment** (`c7a6593`). Memory was capped; CPU, PIDs and disk were not.
Any of the three let one seat end the class.

- **CPU**: `cpu_limit`, a hard CFS quota defaulting to a quarter of the box
  (`os.cpu_count()` reports the *host's* CPUs from inside the hub container).
  Relative weights were considered and rejected — when every seat carries the
  same weight, equal weights are the same as no limit.
- **PIDs**: `pids_limit` 512 via `extra_host_config`, against a measured peak of
  78. This was the gap neither the user nor I had on our lists, and it is the
  fastest way to kill the box: a fork bomb exhausts the host's shared process
  table in seconds and takes dockerd and the hub, not the student.
- **Disk**: a per-seat loop-mounted ext4 image (`scripts/seat-storage.sh`),
  bind-mounted at `/home/jovyan`. Docker cannot cap a named volume —
  `--storage-opt` applies to the writable layer, not volumes.

**Sizing** (`20981a6`). `LAB_PLAN_PERCENT` is gone. Sizing derives from
`LAB_PEAK_MIB` (measured), the cap stays as a separate protective ceiling, and
the report prints the oversubscription factor instead of leaving it silent.
Three-branch rule for which peak applies: an explicit measurement wins; ours
applies while the cap it was taken against still holds; otherwise plan at the
cap, because no measurement exists for one that size.

**PRINCIPLES.md** (`9d9c62f`). The user's five principles verbatim, each with
what it rules out, plus the precedence rule (2 beats 3) and an open-gaps list.

**Docs** (`9312e7a`). README, SPEC and DEVELOPMENT described named volumes, a
single memory ceiling and a sizing model none of which survived. SPEC's status
line had been stale since 2026-09-18 and its sizing table had survived two

## Decisions and rules

- **`mkfs.ext4 -E nodiscard` is load-bearing, not tuning.** mke2fs discards by
  default, which on a file punches holes through the blocks `fallocate`
  reserved. Removing that flag makes every seat image sparse, every seat
  overcommits the same free space, and containment silently stops being real.
- **Per-seat filesystems, not project quotas.** Quotas are thinner and more
  standard; they were rejected because Docker Desktop's kernel is built without
  `CONFIG_QUOTA`/`CONFIG_QFMT_V2`, so they cannot be tested outside production.
  Testability won deliberately. Revisit only if local testing stops mattering.
- **Every ceiling is a ceiling, not a reservation.** Seats are deliberately
  oversubscribed; sizing does not assume everyone pegs everything at once. Do
  not "fix" this by planning at the cap — that is the bug that was just removed.
- **Sizing derives from measured peak, never from the cap.** The cap answers
  "when do we kill one student"; the box answers "when does the host die".
- **PRINCIPLES.md outranks SPEC and every code comment.** When a design rule
  produces a principle violation, the rule is wrong.
- **Assertions need floors.** A test that generates no load must fail, not pass.
- **Never attribute commits to Claude Code or Anthropic** — the user's global
  CLAUDE.md rule. Commits went straight to `main`, matching repo convention.

## Traps

Carried forward, plus what cost time here:

- **`mkfs.ext4` silently makes a preallocated image sparse.** Measured 268435456
  bytes before, 339968 after. Every command reports success.
- **On a laptop, dockerd lives in its own mount namespace** (`mnt:[4026532553]`
  vs PID 1's `mnt:[4026531841]`). A loop mount made in the VM's init namespace
  is invisible to the daemon, so the bind-mount silently resolves to the
  underlying directory: the student container comes up with the whole 1 TB VM
  disk at `/home/jovyan` and no limit, reporting success throughout. This is why
  `scripts/dev-seats.sh` exists; on the box there is no such split.
- **`docker exec` cannot get a PID while the container's process table is full.**
  The fork probe leaves ~506 processes sleeping; the next test then silently
  fails to start and, before the floor check existed, reported a pass.
- **`pids.peak` can legitimately exceed `pids.max`** (observed 517 vs 512) —
  migrated tasks charge past the limit. Asserting `peak <= max` fails a working
  cap. Assert that creation was *refused* instead.
- **Docker's local volume driver cannot do `o=loop`** — it passes `o` as mount
  data, not a flag, and fails with `loop: invalid argument`.
- **`claude -p` does not inherit `--dangerously-skip-permissions`.** Students get
  it from `student-image/skel/.lab-bashrc:40`. Without the flag, a headless probe
  produces confident prose and executes nothing.
- **`/home/jovyan/.npm` is root-owned in the student image.** Harmless in a real
  spawn — the home mount shadows it — but a bare `docker run` of the image
  cannot `npm install`. Set `HOME` to a writable path when probing the image
  directly.
- **An expired SSO token looks exactly like a missing resource.** `discover`
  returns empty arrays; so does an instance-type lookup.
- **`docker compose up` can silently reuse a stale `lab-hub` container.**
- **Logging into JupyterHub by script needs the `_xsrf` token** from the login
  page; copy the sequence from `scripts/test-e2e.sh:28-33`.
- **`c.JupyterHub.log.warning(...)` sets a config value; it does not log.**
- **Let's Encrypt allows 5 duplicate certs per week per hostname.** A rehearsal
  plus a class is 2.
- **The `dcg` guard blocks recursive-force deletes** even inside a quoted remote
  command or a heredoc that merely names one. Use
  `find ... -mindepth 1 -depth -delete`, and write documents with the Write tool.
